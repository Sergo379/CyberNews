# Вопросы к защите

1. **Что такое Docker?** Инструментарий сборки образов и запуска контейнеров. В CyberNews Docker Desktop запускает Linux-образы сервисов.
2. **Что такое контейнер?** Изолированный процесс с файловой системой образа и заданными ресурсами. Сервис Auth использует свой контейнер и HTTP API.
3. **Чем он отличается от виртуальной машины?** Контейнеры разделяют ядро хоста. В Windows здесь ядро Linux предоставляет WSL 2.
4. **Что такое Dockerfile?** Рецепт сборки образа. Например, [Dockerfile Auth](../services/auth/Dockerfile) устанавливает Python-зависимости и задаёт UID 10001.
5. **Что такое Docker image?** Версионируемый набор слоёв и конфигурация запуска. Образы лабораторной доступны под именами `cybernews/<service>:lab3`.
6. **Что делает Docker Compose?** Описывает сеть, девять контейнеров и постоянные тома. Рабочая и учебная версии работают параллельно. [Compose](../compose.yaml).
7. **Для чего Kubernetes?** Поддерживает нужное состояние приложений, маршрутизацию, проверки, масштабирование и восстановление после отказа Pod.
8. **Чем он отличается от Compose?** Kubernetes использует API и контроллеры поверх узлов. Compose описывает запуск проектов на Docker Engine.
9. **Что такое кластер?** Управляющая плоскость и рабочие узлы. В проверенном стенде управляющая плоскость и Pods находятся на одном узле Docker Desktop kind.
10. **Что такое Node?** Среда, где kubelet через containerd запускает Pods. Здесь он называется `desktop-control-plane`.
11. **Что такое Pod?** Наименьшая единица планирования. В CyberNews приложение работает в одном контейнере Pod, у которого есть собственный сетевой адрес.
12. **Что такое Deployment?** Контроллер stateless приложений с числом реплик и стратегией обновления. Таких объектов семь, включая Gateway.
13. **Что делает ReplicaSet?** Поддерживает нужное число Pods по шаблону Deployment. Он создаёт замену удалённой Community-реплики.
14. **Что такое Service?** Стабильная сетевая точка, выбирающая Pods по labels. Сервис Community ведёт к Ready адресам его EndpointSlices.
15. **Зачем ClusterIP?** Это внутренний виртуальный адрес Service. Для браузера порт Gateway доступен через отдельный loopback port-forward.
16. **Как работает DNS Kubernetes?** CoreDNS разрешает имена Services. Nginx читает DNS-сервер из Pod и строит полные имена внутри namespace.
17. **Что такое Namespace?** Логическая группа объектов Kubernetes. `cybernews-lab3` ограничивает область проверок и имеет свой набор ресурсов.
18. **Что такое ConfigMap?** Несекретная конфигурация. Через неё передаются адреса API, параметры RSS и файлы инициализации.
19. **Что такое Secret?** Kubernetes-объект для учётных данных. В лабораторной восемь неизменяемых Secrets, Base64 не является шифрованием хранилища.
20. **Что такое StatefulSet?** Контроллер для Pods со стабильными именами. `postgres-0` и `rabbitmq-0` используют отдельные постоянные тома.
21. **Чем StatefulSet отличается от Deployment?** StatefulSet сохраняет сетевую идентичность и порядковое имя. Deployment заменяет взаимозаменяемые реплики.
22. **Что такое PersistentVolume?** Подготовленное кластером физическое или логическое хранилище. Лабораторные PV создаёт local-path provisioner.
23. **Что такое PersistentVolumeClaim?** Запрос приложения на объём и режим доступа. Два PVC по 2 GiB монтируются независимо от жизни Pod.
24. **Зачем StorageClass?** Она определяет provisioner, режим привязки и политику высвобождения. Здесь default — `standard`.
25. **Что проверяет liveness?** Живость процесса. Backend возвращает `/health` даже при временной потере PostgreSQL.
26. **Что проверяет readiness?** Способность обслуживать запросы. `/ready` возвращает 503 при недоступной базе, и EndpointSlice перестаёт считать Pod готовым.
27. **Что такое startup probe?** Даёт контейнеру отдельное окно на запуск до включения регулярных probes. Это особенно важно для PostgreSQL и RabbitMQ.
28. **Что задают requests и limits?** Requests участвуют в планировании. CPU limit ограничивает потребление, memory limit может привести к OOM при превышении.
29. **Что такое горизонтальное масштабирование?** Изменение количества реплик. В эксперименте Community вырос с одной до трёх Ready реплик.
30. **Как Service балансирует трафик?** kube-proxy направляет соединения на готовые endpoint-адреса. Запросы проверялись по общему префиксу `X-Request-ID` в логах каждого Pod.
31. **Что происходит при удалении Pod?** Он уходит из выдачи готовых endpoints, а ReplicaSet создаёт другой Pod. У одиночной реплики в это время возможен перерыв.
32. **Почему PostgreSQL нельзя увеличить с 1 до 3 как API?** Несколько независимых процессов не должны писать в один каталог данных. Для HA понадобятся отдельные тома, репликация и управление failover.
33. **Почему миграции выполняет Job?** Job завершается после `alembic upgrade head`. Обычные Pods стартуют без конкурентного обновления схемы при scale.
34. **Что происходит при остановке RabbitMQ?** Публикация Articles может завершиться с записью в outbox. После возврата брокера Dispatcher повторяет передачу.
35. **Как работает transactional outbox?** Первая публикация и строка события записываются одной транзакцией. Dispatcher отмечает доставку после publisher confirm.
36. **Что происходит с PostgreSQL при замене Pod?** Новый `postgres-0` использует прежний Bound PVC и открывает существующий `PGDATA`.
37. **Почему локальный PVC не защищает от потери диска?** Файлы PV находятся на одном локальном узле. Устойчивость к потере узла, резервные копии и репликация — самостоятельные задачи.
38. **Почему Collector остаётся один?** Планировщик использует advisory lock, но переход лидерства и поведение таймеров при нескольких репликах требуют отдельного эксперимента.
39. **Почему масштабировали Community?** Состояние комментариев, реакций и закладок находится в общей PostgreSQL. Поэтому реплики читают одни данные, а уникальные ключи удерживают одну реакцию пользователя.
40. **Какие ограничения у стенда?** Один узел и по одной реплике PostgreSQL и RabbitMQ, локальный диск и HTTP через loopback. [Наблюдения и границы проверки](REPORT.md).
