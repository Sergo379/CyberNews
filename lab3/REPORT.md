# Технический отчёт. CyberNews в Kubernetes

## Цель и постановка

Лабораторная работа №3 переносит приложение из лабораторной №2 в локальный Kubernetes. Проверяются отдельные Deployments, сетевой доступ, Secrets, хранилища, probes, управление ресурсами, масштабирование и восстановление. Параллельный Docker Compose обслуживает рабочий CyberNews на порту 8080. [Методичка PAD](https://github.com/Randwow/PAD#лабораторная-работа-3-docker-и-kubernetes) · [Материалы лабораторной №2](../lab2/README.md).

## Среда и границы приложения

В Windows 11 выбран встроенный Docker Desktop 4.99.0 с kind, поскольку на машине уже работали Linux-контейнеры. После включения `kubectl` подтвердил Kubernetes v1.36.1, контекст `docker-desktop` и Ready-узел `desktop-control-plane`. Для CyberNews создан отдельный namespace `cybernews-lab3`. На узле доступны 12 CPU и 7 983 884 KiB памяти. [Архитектура](diagrams/kubernetes-architecture.md).

Auth, Collector, Articles, Community, Moderation и Notifications сохранили Dockerfile, Python, FastAPI, модели и REST-контракты. В Kubernetes каждый сервис имеет отдельный Deployment. Nginx в седьмом Deployment использует собственный образ со статическим frontend, DNS-резолвером Pod и полными DNS-именами Services. Обычные приложения стартуют с одной репликой, проверками состояния и RollingUpdate. Backend запускается с UID 10001, Gateway с UID 101. У приложений отключено монтирование токена Kubernetes API. [Манифесты](../k8s/README.md).

## Сеть, конфигурация и данные

Семь ClusterIP Services обслуживают приложения. StatefulSets доступны через два обычных и два headless Services, всего одиннадцать Services. Port-forward публикует Kubernetes Gateway на `127.0.0.1:18080`. Nginx сохраняет префиксы REST, Swagger, CSP, перенаправления страниц и запрет служебных маршрутов. Восемь NetworkPolicy ограничивают ingress, разрешая связи Gateway, шести backend, Jobs, PostgreSQL и RabbitMQ. На указанном CNI действие правил проверено сетевым запросом из отдельного Pod. Исходящие подключения Collector к RSS остаются доступны. [Сеть](diagrams/networking.md) · [Правила ingress](../k8s/networkpolicies/ingress.yaml).

Несекретные параметры подаются через ConfigMaps, а восемь отдельных immutable Secrets — через ссылки в Pod. Секреты генерируются криптографически стойким генератором, отличаются от значений Compose и исключены из Git. Deploy отказывается заменять существующие credentials несовпадающими значениями. Для смены паролей в локальной базе, брокере и потребителях потребуется согласованная процедура ротации. Кодирование Secrets в Base64 не означает шифрование etcd. [Скрипт развёртывания](../scripts/lab3-deploy.ps1).

PostgreSQL хранит шесть изолированных UTF-8 баз. В двух выделенных RWO PVC `postgres-data` и `rabbitmq-data` хранятся база и состояние брокера. RabbitMQ использует постоянное имя `rabbit@rabbitmq-0`. При инициализации PostgreSQL использован исходный SQL-инициализатор Compose через ConfigMap. Существующий `PGDATA` повторно не инициализируется. [Хранилища](diagrams/storage.md).

В Deployment миграции отключены выбором команды запуска. Шесть отдельных Jobs запускают Alembic под сервисной ролью каждого приложения и завершаются до запуска приложений. Повторное развёртывание создаёт новые Jobs и проверяет те же ревизии. Ready Articles требуется до первого запуска Collector, иначе стартовый RSS-сбор может опередить доступность каталога. [Миграции](../k8s/jobs) · [Порядок запуска](../scripts/lab3-deploy.ps1).

## Probes и ресурсы

У backend `/health` проверяет процесс и используется для startup и liveness, `/ready` — готовность работы с его зависимостями. Gateway отвечает на `/health`, а PostgreSQL и RabbitMQ проверяются нативными утилитами. Во время эксперимента с PostgreSQL прямой Pod-процесс Articles продолжил отвечать на `/health` кодом 200, `/ready` вернул 503, а Service исключил неготовый endpoint. После восстановления Pod вернулся в Ready с прежним числом рестартов. [Протокол](EVIDENCE.md).

Запросы backend 100m CPU и 128Mi RAM позволяют уместить по одной реплике всех приложений и временно добавить две Community. Лимиты 500m и 512Mi ограничивают их вклад. PostgreSQL и RabbitMQ получили большие лимиты 768Mi и 1Gi для persistent storage и очередей. Одноузловой стенд сохраняет достаточный бюджет для управляющей плоскости и работающего Compose. [Таблица ресурсов и конфигурации](README.md#ресурсы-и-доступ).

## Эксперименты

- **Масштабирование.** Community запущен с одной реплики, переведён на три, затем возвращён к исходному масштабу. Готовность проверена по EndpointSlices. Один и тот же ресурс был доступен через Service, конкурентные одинаковые реакции оставили один голос. Логи с идентификаторами запросов подтвердили трафик ко всем трём Pods. [Схема](diagrams/scaling.md).
- **Восстановление.** После удаления одного из трёх Community Pods ReplicaSet создал замену. Gateway продолжал возвращать 200 через оставшиеся endpoints. Отдельно проверена замена единственного Pod. Записанный комментарий остался доступен. [Схема](diagrams/recovery.md).
- **PostgreSQL.** После контролируемой остановки и запуска StatefulSet изменился UID Pod. UID PVC и имя PV остались прежними. Сохранены проверочная учётная запись, статья и комментарий.
- **RabbitMQ.** Устойчивое сообщение осталось в очереди после пересоздания Pod. Публикация во время отказа сохранила запись в outbox. После возвращения брокера и потребителя обе статьи дали по одному уведомлению. Действующие exchange, routing key, quorum queue и DLQ сохранены.

Конкретные команды, результаты и доказательства доступны в [протоколе](EVIDENCE.md).

## Исправления и ограничения

При первом развёртывании контейнеры получили `ErrImageNeverPull`. Containerd узла kind оказался отдельным от хранилища Docker CLI. Добавлен импорт образов в подтверждённый узел и проверка их идентификаторов. Первоначальный Collector закончил импорт ошибкой недоступности Articles; порядок запуска изменён, дополнительный сбор после готовности сервисов импортировал реальные новости. Для Windows исправлена передача `--` во вложенную команду kubectl и вывод унифицирован с терминальными кодировками.

Локальный кластер ограничен одним узлом с локальными дисками. Реплики Community повышают устойчивость к замене отдельного Pod, а потеря узла остаётся общим отказом. Кластер работает по локальному HTTP через port-forward. Collector, Articles, Notifications, PostgreSQL и RabbitMQ в экспериментах сохранены в одном экземпляре. Масштабирование фоновых обработчиков и действительная многозонная отказоустойчивость требуют дополнительных испытаний.

## Вывод

CyberNews развёрнут как отдельный набор Kubernetes-ресурсов. Работа API и браузера, смена числа реплик, замена Pods и сохранность PostgreSQL и RabbitMQ подтверждены на изолированных данных. Рабочий Compose проверен отдельно. [Матрица соответствия](REQUIREMENTS_MATRIX.md).
