# Архитектура CyberNews

## Сервисы и данные

| Сервис | Граница ответственности | База и роль | Префикс API |
| --- | --- | --- | --- |
| Auth | Учётные записи, роли, JWT и отдельная административная авторизация | `auth_db`, `auth_svc` | `/api/v1/auth/` |
| Collector | RSS-источники, расписание и сбор новостей | `collector_db`, `collector_svc` | `/api/v1/collector/` |
| Article | Статьи, категории, поиск и ссылки на первоисточник | `article_db`, `article_svc` | `/api/v1/articles/` |
| Community | Комментарии, реакции и избранное | `community_db`, `community_svc` | `/api/v1/community/` |
| Moderation | Жалобы, ограничения и журнал модерации | `moderation_db`, `moderation_svc` | `/api/v1/moderation/` |
| Notification | Подписки и уведомления | `notification_db`, `notification_svc` | `/api/v1/notifications/` |

Сервисы запускаются отдельными процессами FastAPI и собираются в отдельные образы. Общий код из `services/runtime/` копируется в каждый образ на этапе сборки. Сервис владеет собственной базой. Модели добавляются через `Base` из его `app/models.py`. Все шесть приложений имеют отдельные каталоги Alembic и используют свои строки подключения. Обмен данными между сервисами идёт через API или события.

Первичный скрипт PostgreSQL выполняется официальным Docker entrypoint на пустом томе. Он создаёт шесть баз UTF-8 и шесть ролей с правом подключения только к своей базе. Все шесть движков SQLAlchemy используют драйвер psycopg и адрес `postgres:5432`. Данные PostgreSQL и RabbitMQ хранятся в разных именованных томах.

## Контракт Gateway

Nginx принимает запросы к `/api/v1/{service}/…` и удаляет ровно этот префикс, сохраняя начальный слеш оставшегося пути и параметры запроса. Например, `/api/v1/articles/ready` поступает в `http://articles:8000/ready`. Определяйте маршруты FastAPI относительно корня приложения. Используйте завершающий слеш для корневого URL сервиса. Gateway возвращает `404` для неизвестных префиксов. TLS и публичный сетевой доступ относятся к будущему развёртыванию.

В сети Compose доступны `http://auth:8000`, `http://collector:8000`, `http://articles:8000`, `http://community:8000`, `http://moderation:8000` и `http://notifications:8000`. Nginx выполняет DNS-разрешение через Docker DNS и обновляет адреса upstream после пересоздания контейнера. Переменные `*_UPSTREAM` задают внутренние адреса. Gateway имеет собственную проверку `/health`; готовность каждого сервиса определяется по его `/ready`.

Gateway передаёт `X-Request-ID` сервису. Оба компонента принимают идентификаторы из латинских букв, цифр, точки, дефиса и подчёркивания длиной до 128 символов и генерируют свой идентификатор при отсутствии корректного значения. Приложения и журнал запросов Nginx пишут JSON в stdout или stderr. Ошибка готовности содержит имя сервиса и статус зависимости. Диагностика приложения сообщает тип ошибки подключения без строки подключения или текста исключения драйвера.

## Авторизация и модерация

Auth владеет учётными записями, хешами паролей, версиями авторизации, административными сессиями и аудитом полномочий. JWT содержит UUID аккаунта и версию авторизации, а текущие роль и статус проверяются по Auth для каждого защищённого действия. Смена основного пароля, роли или статуса аннулирует ранее выданные JWT через изменение версии и удаляет административные сессии. Восстановление требует нового входа. Действия, уже принятые другим сервисом на основании успешной проверки, завершаются в его локальной транзакции.

Moderation владеет жалобами, ограничениями комментирования и собственным аудитом. UUID пользователей в `moderation_db` ссылаются на Auth через внутренний HTTP-контракт. Сервисы подтверждают подлинность вызова отдельным секретом. Nginx закрывает пути `/internal/` и удаляет переданный клиентом `X-Internal-Key`. Moderation возвращает `503`, когда Auth не может подтвердить критическую операцию.

Сервисы записывают локальные изменения вместе с соответствующими событиями аудита. Для межсервисного скрытия комментариев Moderation хранит команду, а Community сохраняет её результат вместе с изменением статуса. Moderation записывает аудит после подтверждения результата. Для сопоставления операций используйте время, UUID объекта, UUID команды и `request_id`. Модераторы видят собственный аудит, Super Admin — полный аудит каждого сервиса. [Контракты Auth и Moderation](AUTH_MODERATION_API.md).

## Сбор и публикация новостей

Collector планирует периодические и ручные синхронизации, загружает RSS и Atom из разрешённых публичных источников и сохраняет историю попыток. Он передаёт статьи в Articles по защищённому внутреннему REST API. Articles применяет уникальные ключи URL и GUID, классифицирует публикации по ключевым словам и индексирует заголовки и описания для полнотекстового поиска в PostgreSQL. Каталог публикует только выбранный редакционный статус.

Политика источника и её версия переходят из Collector в Articles. Полный внешний текст доступен после документированного разрешения, а снятие разрешения применяется к уже сохранённым статьям. Для собственных статей предусмотрены создание, редактирование, скрытие и восстановление. Административные операции используют действующую сессию Super Admin из Auth. Примеры маршрутов, правила загрузки и контракт `article.published` описаны в [руководстве RSS и каталога](NEWS_RSS_API.md).

## Community и уведомления

Community подтверждает пользователя через Auth, доступность статьи через Articles и право комментирования через Moderation. В базе Community остаются только UUID сторонних ресурсов и снимок никнейма автора. Пакетные проверки статей позволяют выдавать статистику, комментарии и избранное с актуальной видимостью.

Articles записывает первое событие публикации в outbox и доставляет его через RabbitMQ vhost `cybernews` на `rabbitmq:5672` с подтверждением брокера. Notifications дедуплицирует событие и сохраняет уведомления подписчиков до подтверждения доставки. Заголовки уведомлений запрашиваются у Articles с проверкой видимости. [Модели, маршруты и доставка сообщений](COMMUNITY_NOTIFICATIONS_API.md).

## Браузерный интерфейс

Nginx монтирует `frontend/` только для чтения и обслуживает публичную точку входа и административную точку входа `/admin/`. Маршруты страниц используют History API. Служебные и API-маршруты исключены из перенаправлений интерфейса. Сценарии, стили и словари доступны с того же origin. API-ответы передаются с `Cache-Control: no-store`.

Публичная часть запрашивает реальные записи шести сервисов через Gateway, локализует интерфейс на RU/EN и сохраняет исходный язык материалов. Вкладка хранит JWT в `sessionStorage`. Административная сессия с отдельным паролем хранится в памяти и теряется при обновлении страницы. Правила доступа применяют Auth и сервис, выполняющий действие. [Руководство по интерфейсу](FRONTEND_GUIDE.md).

## Выбор технологий и компромиссы

Альтернативы ниже описаны как варианты проектирования. Эксперименты лабораторной сравнивают поведение выбранной реализации при штатном запуске и отказе зависимостей.

| Решение | Назначение | Альтернатива и компромисс |
| --- | --- | --- |
| FastAPI и Pydantic | REST, проверка входа и OpenAPI из деклараций | Flask даёт меньше встроенных соглашений. Модели FastAPI упрощают контракт ценой явной поддержки схем |
| PostgreSQL | Транзакции, полнотекстовый поиск, уникальные и частичные индексы | SQLite удобен в одном процессе. PostgreSQL требует отдельного узла и управления доступом |
| Раздельные базы и Alembic | Владение данными, отдельные роли и история схем | Схемы в общей базе проще обслуживать централизованно. Шесть баз добавляют конфигурацию и исключают межсервисные SQL-соединения между сервисами |
| REST | Немедленное подтверждение роли, доступности статьи и результата команды | gRPC даёт типизированный контракт с генерацией клиентов. REST удобнее проверять через HTTP и Swagger, но требует валидации и сетевых тайм-аутов |
| RabbitMQ | Устойчивая очередь, подтверждения, повтор доставки и DLQ | Kafka ориентирована на журнал событий с повторным чтением. RabbitMQ вписывается в сценарий очереди задач, но добавляет отдельный компонент |
| События для уведомлений | Отвязать публикацию от создания записей для подписчиков | Синхронный HTTP-вызов упрощает быстрый путь, но делает запись публикации зависимой от Notifications |
| Transactional outbox | Атомарно сохранить событие с первой публикацией | Прямая публикация в брокер требует согласовать два независимых commit. Outbox требует диспетчера, таблицы и дедупликации потребителя |
| Nginx | Один origin, проксирование API, статика и корреляция запросов | Прямые порты усложняют клиентскую конфигурацию и увеличивают поверхность доступа. Nginx становится общим входным компонентом |
| JWT и admin session | Межсервисная проверка идентификатора и отдельное повышение полномочий | Обычная серверная сессия требует общего хранилища для проверки. Текущий JWT остаётся отзывным благодаря версии и проверке аккаунта в Auth |
| Vanilla JavaScript | Локальный SPA-интерфейс ES modules на существующем Gateway | React/Vue облегчают крупные интерфейсы, но добавляют сборку и зависимости. Для текущего объёма маршрутизацию и состояние поддерживает браузерный код |
| Docker Compose | Воспроизводимый локальный запуск сетей, образов, томов и healthchecks | Запуск процессов вручную требует синхронизировать параметры и БД. Compose на одном хосте не даёт кластерной отказоустойчивости |

## Несколько реплик

Collector использует PostgreSQL advisory lock для одного активного планировщика и ограничение одного активного запуска. В Kubernetes потребуется проверить выбор лидера после остановки pod и соединение, удерживающее lock. Dispatcher Articles берёт строки через `FOR UPDATE SKIP LOCKED`. Несколько воркеров могут отправлять разные строки, а упорядочивание между ними остаётся отдельным вопросом. Notifications использует уникальный `event_id` и транзакцию перед ACK. Moderation сохраняет команды и результаты исполнения. Перед масштабированием нужно проверить конкурентное взятие задач, повтор доставки и остановку воркеров в заданный grace period.

Auth и Community сохраняют счётчики лимитов в собственных базах. При нескольких репликах они разделяют одну квоту при подключении к той же базе. При смене ingress проверьте определение адреса клиента для лимита Auth. Разнесите миграции, запуск приложений и ожидание зависимостей, чтобы схему обновляла одна задача. Для публичного контура понадобятся TLS, защищённая поставка секретов, устойчивое хранилище и резервное копирование. [План лабораторной №3](../lab3/README.md).
