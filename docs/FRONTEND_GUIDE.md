# Интерфейс CyberNews

## Запуск

Из корня проекта в PowerShell запустите рабочий Docker Compose. Nginx обслуживает статические файлы, а новые версии серверного кода собираются той же командой.

```powershell
.\scripts\init-env.ps1
docker compose up -d --build
docker compose exec -T gateway nginx -t
docker compose ps
```

Откройте [главную страницу](http://localhost:8080/). Первый Super Admin создаётся интерактивной командой в контейнере Auth.

```powershell
docker compose exec auth python -m app.bootstrap
```

## Маршруты

| Адрес | Назначение |
| --- | --- |
| / | Лента, категории, источники, поиск, фильтры и пагинация |
| /article/{uuid} | Публикация, ссылка на первоисточник, реакции, обсуждение и жалобы |
| /login, /register | Вход и регистрация |
| /profile | Никнейм, email, роль, даты и смена пароля |
| /bookmarks | Приватные закладки |
| /subscriptions | Подписки на категории |
| /notifications | Уведомления, фильтр и отметки прочтения |
| /admin/ | Обзор и вход в административную панель |
| /admin/reports, /admin/comments, /admin/restrictions, /admin/audit | Модерация и аудит |
| /admin/users, /admin/articles, /admin/sources | Управление пользователями, публикациями и RSS |

History API поддерживает прямые ссылки, обновление страницы и переходы назад и вперёд. Параметры ленты хранят поиск, сортировку, фильтры и смещение. Неизвестный клиентский маршрут отображает страницу «Страница не найдена».

## Файлы и оформление

- **frontend/index.html**, **frontend/admin/index.html** — точки входа публичной части и панели.
- **frontend/js/app.js** и **router.js** — запуск приложения, маршрутизация и отмена устаревших запросов.
- **frontend/js/pages/** — лента, публикации, формы и личный кабинет. **frontend/js/admin/** — административные сценарии. **frontend/js/components/** — навигация, элементы форм, диалоги, таблицы и безопасная сборка разметки публикаций.
- **frontend/css/** — цветовые и типографические переменные, базовые стили, макет, компоненты, публичные страницы и панель.
- **frontend/locales/** — соответствующие словари RU/EN. Код категорий поступает из Articles. Даты форматируются через Intl.DateTimeFormat. Публикации, имена источников, комментарии и никнеймы отображаются в исходном виде.

Цвета и состояния компонентов определены CSS-переменными. Пользователь может выбрать светлую или тёмную тему либо следовать системному предпочтению. Язык и тема сохраняются в localStorage. Переключение языка сохраняет маршрут и введённые несекретные поля основных форм. Каталог перестраивает число колонок, а административные таблицы прокручиваются внутри контейнера. Мобильное меню и окна используют нативный dialog, закрытие по Escape и восстановление фокуса. Поля используют размер шрифта не менее 16 px и учитывают безопасные области экрана.

## API и права

| API Gateway | Что использует интерфейс |
| --- | --- |
| /api/v1/auth/ | Регистрация, вход, профиль, пароль, повышение полномочий, поиск обычных пользователей, управление ролями и аудит |
| /api/v1/articles/ | Каталог, категории, источники, статьи и редактор |
| /api/v1/community/ | Пакетная статистика ленты, комментарии, реакции и закладки |
| /api/v1/moderation/ | Разрешение на комментарии, жалобы, ограничения, команды над комментариями и аудит |
| /api/v1/notifications/ | Подписки, непрочитанный счётчик и отметки прочтения |
| /api/v1/collector/ | Управление источниками, разрешения, статус и история запусков |

Все запросы идут на тот же origin через модуль API. Он отображает состояния ошибок и очищает недействительные сеансы. JWT хранится в sessionStorage текущей вкладки и проверяется через /me при запуске. Выход очищает локальное состояние, а смена основного пароля отзывает выданные JWT на сервере. Токен административной сессии хранится только в оперативной памяти, передаётся вместе с JWT и теряется при F5 или закрытии вкладки. Auth определяет его действительный срок, ограниченный 15 минутами. После истечения или команды блокировки панель запрашивает отдельный пароль. Для первоначальной установки административного пароля требуется основной пароль.

Guest читает каталог и обсуждения. User получает подписки, закладки, действия сообщества и жалобы. Moderator рассматривает жалобы, скрывает комментарии обычных пользователей, назначает ограничения комментирования и видит доступные ему записи Moderation. Super Admin дополнительно снимает ограничения, восстанавливает комментарии, управляет ролями, обычными аккаунтами, статьями, RSS и аудитом четырёх сервисов. Сервер проверяет каждую защищённую операцию. Для поиска целей ограничений Auth выдаёт панельному пользователю только никнейм и UUID активного обычного аккаунта. При модерации комментария проверка автора по UUID охватывает и заблокированные обычные аккаунты.

Создание и правка комментария требуют разрешения Moderation. При недоступности сервиса форма объясняет причину, а удаление собственного комментария остаётся доступно согласно политике Community. Закладки и уведомления учитывают доступность публикации по ответу API. Когда уведомление скрытой статьи остаётся в списке, UI показывает нейтральное сообщение. Счётчик проверяется раз в минуту в активной вкладке и после действий с уведомлениями.

## Публикации и защита

Внешние материалы без подтверждённых прав показывают выдержку и ссылку на издателя. Редактировать полный текст можно у собственных статей. Для RSS с полным текстом или изображениями Collector требует запись о разрешении. Article Service очищает HTML. Браузер повторно собирает разрешённые элементы и атрибуты, а пользовательские строки вставляет текстовыми узлами. Внешние ссылки ограничены HTTP(S) и открываются с noopener и noreferrer.

Nginx монтирует frontend в режиме read-only, разделяет базовые документы и применяет History API fallback только к страницам. HTML проверяет свежесть при загрузке, статика кешируется пять минут, API выдаёт Cache-Control: no-store. Политика CSP разрешает сценарии, стили и сетевые запросы с текущего origin, а также допустимые HTTP(S)-изображения. Дополнительно применяются nosniff и Referrer-Policy. Префиксы API и служебные пути отделены от интерфейса. Маршрут /health возвращает JSON. Swagger и OpenAPI доступны через Gateway.

## Браузерные проверки

Подготовьте тестовые зависимости. Для установленного Edge задайте канал msedge. Для WebKit можно установить тестовый браузер и указать движок webkit.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r tests\stage5-requirements.txt
$env:CYBERNEWS_BROWSER_CHANNEL = 'msedge'
.\scripts\smoke-test-stage5.ps1 -PythonExe .\.venv\Scripts\python.exe
```

Скрипт поднимает отдельный проект Compose с временными базами, брокером и RSS-фикстурами. Он проверяет изменение данных, модерацию и публикацию на стенде. Чтение реального каталога, навигацию и оформление проверяет отдельная команда.

```powershell
$env:CYBERNEWS_LIVE_READONLY_URL = 'http://localhost:8080'
.\.venv\Scripts\python.exe -m pytest -q tests\test_stage5.py -k live_catalog
```

Снимки сохраняются в .test-artifacts/stage5. Playwright проверяет реальные DOM-состояния, ошибки JavaScript и нарушения CSP. Эмуляция мобильного viewport и тестовый WebKit дают проверку макета и браузерного движка. Результаты зависят от фактической модели устройства и версии Safari.

## Известные ограничения

Поиск прямо в таблицах пользователей и журналов фильтрует текущую страницу. Пагинация источников, жалоб и журналов обращается к API. Для восстановления пароля и автоматического обновления JWT в Auth отсутствуют публичные API. Время доставки уведомления зависит от фоновой публикации события и RabbitMQ. Локальный Nginx слушает loopback по HTTP. Для внешнего размещения потребуется отдельная настройка TLS.
