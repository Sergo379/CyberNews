# Вопросы преподавателя

1. **Что такое микросервисная архитектура?** Это разбиение системы на процессы со своими контрактами и ответственностью. В CyberNews границы процессов и сборок видны в [Compose](../compose.yaml).
2. **Почему шесть микросервисов?** Учётные записи, импорт RSS, каталог, обсуждения, модерация и уведомления имеют разные данные и жизненные циклы. [Границы сервисов](../docs/ARCHITECTURE.md#сервисы-и-данные).
3. **Чем это отличается от монолита?** Сервисы собираются и запускаются по отдельности, а границы данных и вызовов поддерживаются базами и HTTP-контрактами. Такой вариант требует больше инфраструктурных проверок. [Архитектура](diagrams/architecture.md).
4. **Почему Auth вынесен отдельно?** Только Auth определяет действительность аккаунта, роль и версию доступа. Остальные сервисы запрашивают у него подтверждение полномочий. [Auth](../services/auth/app/dependencies.py).
5. **Зачем API Gateway?** Он даёт браузеру единый origin и маршрутизирует шесть API по префиксам. [Конфигурация Gateway](../gateway/default.conf.template).
6. **Что делает Nginx?** Он отдаёт HTML и статику, проксирует API, связывает запросы с X-Request-ID, закрывает внутренние маршруты и применяет отдельную политику заголовков для интерфейса. [Маршрутизация](../gateway/default.conf.template).
7. **Зачем каждому сервису своя база?** Владелец схемы меняет данные и миграции в рамках своего домена. Сервисная роль имеет CONNECT только к своей базе. [Инициализация](../infrastructure/postgres/10-initialize.sh).
8. **Почему PostgreSQL?** Транзакции нужны для первой публикации вместе с outbox, частичные уникальные индексы — для активных ограничений, полнотекстовый индекс — для каталога. [Articles](../services/articles/app/models.py) · [Moderation](../services/moderation/app/models.py).
9. **Для чего SQLAlchemy?** Модели, запросы, пулы и сессии изолируют работу с PostgreSQL в каждом процессе. [Database](../services/runtime/cybernews_runtime/database.py).
10. **Что делает Alembic?** Ведёт версии схемы каждого сервиса. При старте выполняется upgrade head, а проверка сравнивает базу с актуальным head и моделями. [Запуск миграций](../services/runtime/cybernews_runtime/migration.py).
11. **Как сервисы обмениваются данными?** REST передаёт результат авторизации, доступность ресурса и административные команды. Первая публикация доставляется через RabbitMQ. [Взаимодействие](diagrams/communication.md).
12. **Чем REST отличается от сообщений?** При REST операция ждёт ответа владельца данных. При AMQP факт публикации сохраняется и обрабатывается независимо от ответа HTTP. [Outbox](../services/articles/app/outbox.py).
13. **Зачем RabbitMQ?** Publisher confirms, устойчивая очередь и повторы дают восстановление доставки при временных сбоях. Некорректные сообщения попадают в DLQ. [Топология](../services/runtime/cybernews_runtime/broker.py).
14. **Что при недоступном RabbitMQ?** Публикация и запись outbox завершаются, ожидающая строка сохраняется в PostgreSQL. После восстановления Dispatcher продолжает отправку, а готовность Notifications отражает подключение потребителя. [Проверка отказа брокера](../tests/test_stage4.py).
15. **Что такое transactional outbox?** Это таблица событий той же базы, которая фиксируется в одной транзакции с изменением статьи. [Outbox](../services/articles/app/outbox.py).
16. **Зачем идемпотентность?** При повторной доставке события уникальный event_id предотвращает дубликаты уведомлений. У команд модерации есть собственный ключ и сохранённый результат. [Consumer](../services/notifications/app/consumer.py) · [Команды](../services/moderation/app/comment_commands.py).
17. **Как работает JWT?** Auth подписывает HS256-токен и проверяет подпись, срок действия, issuer, audience и версию доступа аккаунта. [Токены](../services/auth/app/tokens.py) · [Проверка доступа](../services/auth/app/dependencies.py).
18. **Как проверяются роли?** Текущие роль и статус берутся из Auth. Чувствительные операции вызывают доверенную проверку сессии и проверяют достаточность роли. [AdminClient](../services/runtime/cybernews_runtime/admin_client.py).
19. **Почему у администратора отдельный пароль?** Вход в аккаунт выдаёт обычный JWT. Unlock требует отдельный Argon2id-пароль и создаёт краткоживущую сессию, привязанную к jti токена. [Auth API](../services/auth/app/api.py).
20. **Почему Moderator не может снять ограничение?** Операция lift требует зависимость SuperAdmin на стороне Moderation. Роль Moderator позволяет наложить ограничение на обычного пользователя. [Ограничения](../services/moderation/app/api.py).
21. **Как закрыты внутренние API?** Входящий Gateway возвращает 404 для служебных путей и очищает X-Internal-Key. Внутри сети сервисы требуют выделенный ключ. [Gateway](../gateway/default.conf.template) · [Проверка ключей](../services/runtime/cybernews_runtime/security.py).
22. **Что при падении Auth?** Защищённые зависимые операции, где нельзя подтвердить пользователя, возвращают 503. Чтение опубликованных статей из Articles остаётся доступным при работающем PostgreSQL. [Клиент Auth](../services/runtime/cybernews_runtime/service_client.py).
23. **Чем отличаются /health и /ready?** Первый подтверждает живость процесса. Второй проверяет доступность базы и объявленной зависимости, например соединения потребителя с RabbitMQ. [Общий runtime](../services/runtime/cybernews_runtime/application.py).
24. **Как устроены логи?** Запись HTTP-запроса содержит UTC-время, сервис, уровень, идентификатор, сообщение, метод, статус и длительность. [JSON formatter](../services/runtime/cybernews_runtime/logs.py).
25. **Зачем X-Request-ID?** По нему можно связать запись Nginx, запись backend и сообщения доверенных внутренних вызовов, даже если запрос прошёл через несколько процессов. [Доказательство](EVIDENCE.md#журналы-и-rabbitmq).
26. **Как собирается RSS?** Collector ставит запуск в очередь, проверяет разрешённый хост и DNS, загружает с ограничениями и отдаёт нормализованные записи Articles. [Расписание](../services/collector/app/scheduler.py) · [Загрузчик](../services/collector/app/fetch.py).
27. **Почему новости не дублируются?** Articles использует нормализованный URL и GUID источника. Ограничения базы и транзакционная блокировка сохраняют идентичность при повторе и конкуренции. [Импорт](../services/articles/app/ingestion.py).
28. **Где лежат комментарии?** Community хранит текст и снимок никнейма с UUID автора и статьи. Отдельная команда определяет статус скрытия. [Модели](../services/community/app/models.py).
29. **Как проверяли приложение?** Рабочий стенд проверяли на чтение в PowerShell и браузере. Изолированные проекты использовали для pytest, браузерных изменений и остановки зависимостей. [Доказательства](EVIDENCE.md).
30. **Какие есть ограничения?** Локальный HTTP и один узел PostgreSQL/RabbitMQ, допустимость внешнего RSS зависит от источника, количество проверенных реализаций браузеров ограничено Edge и WebKit. [Отчёт](REPORT.md).
31. **Почему Docker удобен?** Отдельные образы фиксируют зависимости, один файл описывает сеть, healthchecks и постоянные тома. В отличие от виртуальной машины контейнеры используют ядро своей базовой ОС. [Compose](../compose.yaml).
32. **Какие варианты рассматривались?** Модульный монолит уменьшил бы сетевые зависимости, а gRPC повысил бы формальность контракта ценой отдельного инструментария. В этой работе REST и отдельные процессы дают понятную демонстрацию установленных границ. [Решения](../docs/ARCHITECTURE.md#выбор-технологий-и-компромиссы).
33. **Что изменится в Kubernetes?** Потребуются Deployments, Services, probes, секреты, хранилище и порядок миграций. При нескольких репликах нужно проверить лидерство Collector, определение IP клиента для лимитов Auth и порядок событий. [План лабораторной №3](../lab3/README.md).
