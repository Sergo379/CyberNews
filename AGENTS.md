# Правила разработки CyberNews

- Сохраняйте шесть самостоятельных микросервисов и их границы ответственности. Обосновывайте необходимость любого нового сервиса архитектурно.
- Сохраняйте совместимость публичного API и правила маршрутизации Gateway. Меняйте контракт только при необходимости и обновляйте документацию.
- Реализуйте только запрошенный объём текущего этапа. Обновляйте документацию и запускайте соответствующие тесты после изменений.
- Поддерживайте Windows 11, PowerShell и Docker Desktop с Linux-контейнерами. Сохраняйте данные Docker и ограничивайте операции ресурсами проекта.
- Храните пароли, токены, ключи и другие секреты вне Git. Используйте локальную конфигурацию и переменные окружения.
- Учитывайте локализацию RU/EN, исходные языки статей и комментариев и роли Guest, User, Moderator, Super Admin.
- Требуйте дополнительную авторизацию в административной панели. Разрешайте снятие административных блокировок исключительно Super Admin. Используйте индивидуальные учётные данные.
- Проверяйте JWT, действующий статус аккаунта, роль и административную сессию сервером для каждого защищённого запроса. При отзыве прав или полномочий аннулируйте соответствующие сессии.
- Передавайте сведения о пользователях через защищённый внутренний API Auth. При отказе нужной проверки отклоняйте действие. Исключайте служебные маршруты из публичного Gateway.
- Применяйте отдельные миграции Alembic в базах Auth и Moderation. Записывайте административное изменение и соответствующую запись аудита в одной транзакции.
- Гоняйте сценарии тестовых администраторов на изолированном стенде. Сохраняйте рабочие базы и тома.
- Перепубликуйте полный текст чужих материалов только с разрешения. В остальных случаях храните допустимое описание и ссылку на оригинал.
- Ограничивайте RSS-загрузчик проверенными публичными доменами и проверяйте разрешённый IP при каждом перенаправлении. Сохраняйте границы загрузки и тайм-аутов.
- Проводите импорт через защищённый REST-контракт Articles. Сохраняйте UUID публикации, дату первоисточника, редакторские изменения и статус скрытия при повторных импортах.
- Проверяйте отзыв прав на внешний контент в Articles и отклоняйте импорт со старой версией политики. Загружайте тестовые RSS только в изолированном стенде.
- Перед созданием и правкой комментария получайте разрешение Moderation и проверяйте публикацию статьи через Articles. Ограничивайте выдачу комментариев, реакций и сведений об избранном для недоступных статей.
- Сохраняйте событие первой публикации в transactional outbox вместе со статьёй. Фиксируйте обработанный UUID события и уведомления одной транзакцией перед подтверждением RabbitMQ.
- Применяйте команды модерации комментариев идемпотентно. Журналируйте подтверждённый результат и сохраняйте возможность восстановить аудит после сбоя между сервисами.
